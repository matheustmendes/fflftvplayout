# Aceite da M2: upload e conversão de comerciais

Roteiro para rodar **na sua máquina**, com um arquivo **real** de comercial
(de preferência um MXF). O objetivo é confirmar o que a nuvem não consegue:
que o seu arquivo converte, e que o áudio e o volume soam certos.

Tempo estimado: 10 a 15 minutos.

## O que você precisa

- O projeto compilado (`cargo build --release -p ffplayout`).
- `ffmpeg` e `ffprobe` no PATH, com `libx264` (`ffmpeg -encoders | grep libx264`).
- Python 3.8 ou mais novo (só a biblioteca padrão; nada a instalar).
- Um comercial real em MXF. Se tiver mais de um tipo (por exemplo um com
  trilhas mono e outro estéreo), teste os dois.

## 1. Subir um servidor de teste (banco separado)

Use um banco e pastas de teste. As migrations 6 e 7 alteram o banco ao
iniciar e não têm volta fácil, então **não aponte para o seu banco de uso**.

**Pastas:** crie-as dentro da sua pasta pessoal. O ffplayout recusa pastas
em `/tmp`, `/root`, `/var`, `/usr`, `/etc` e outras do sistema (a mensagem é
"path must not point to a system directory"). Se você usa o terminal como
`root`, a sua pasta pessoal (`/root`) também é recusada; use outro usuário
ou uma pasta como `/home/<usuario>/ffp-teste`.

```bash
mkdir -p ~/ffp-teste/{storage,logs,public,playlists}

# subir o servidor (deixe rodando neste terminal)
./target/release/ffplayout -l 127.0.0.1:8787 --db ~/ffp-teste/ffplayout.db
```

**Configuração inicial (uma vez).** Em um banco novo o servidor pede o setup.
O jeito mais simples é pelo navegador: abra `http://127.0.0.1:8787`, crie o
administrador e, quando perguntar as pastas, use as de `~/ffp-teste`.

Se preferir pelo terminal (sem navegador), em **outro** terminal, trocando
`SEU_USUARIO` pelo seu nome de usuário do sistema:

```bash
W=/home/SEU_USUARIO/ffp-teste
curl -sS -X POST http://127.0.0.1:8787/api/setup -H 'Content-Type: application/json' -d "{
  \"logs\":\"$W/logs\", \"playlists\":\"$W/playlists\", \"public\":\"$W/public\",
  \"storage\":\"$W/storage\", \"shared\":false,
  \"smtp_server\":\"mail.example.org\", \"smtp_user\":\"ffplayout@example.org\",
  \"smtp_password\":\"\", \"smtp_starttls\":false, \"smtp_port\":465,
  \"username\":\"admin\", \"mail\":\"admin@teste.local\",
  \"password\":\"troque-esta-senha\", \"two_factor\":false }"
```

A resposta esperada é `Setup completed`.

> Não use `ffplayout --init` aqui: ele pergunta SMTP e outros campos no
> terminal e falha com "The input device is not a TTY" quando roda sem
> interação.

## 2. Rodar o teste de fumaça

Em **outro** terminal:

```bash
python3 scripts/dev/commercials_smoke.py \
  --user admin --password 'troque-esta-senha' \
  --sample /caminho/do/comercial.mxf \
  --storage ~/ffp-teste/storage
```

O script faz tudo sozinho: cria anunciante e campanha de teste, envia o
arquivo **pela API de upload** (a mesma que a tela usa), registra o spot,
acompanha a conversão e analisa o arquivo convertido. No fim remove o que
criou (use `--keep` para manter e poder ouvir depois).

Opções úteis:

| Opção | Para quê |
|---|---|
| `--mapping auto\|first_stream\|first_two_mono\|mix_all` | testar outro mapeamento de áudio |
| `--loudness-target -23` | testar outro alvo de volume |
| `--keep` | não apagar o spot e os arquivos |
| `--timeout 1800` | arquivos longos (padrão: 15 minutos) |

## 3. O que conferir

### No resultado do script

Todas as verificações devem **passar**. As principais:

| Verificação | Se falhar, o que significa |
|---|---|
| envia o arquivo (aceita o tipo) | o upload recusou o tipo do arquivo |
| registra o spot (202) | problema de cadastro ou de permissão |
| a conversão terminou no prazo | arquivo muito pesado ou travou; veja o log |
| o spot ficou pronto | veja a mensagem de erro que o script mostra |
| a duração bate (±1 s) | a conversão cortou ou estendeu o vídeo |
| H.264, AAC estéreo 48 kHz | formato de saída inesperado |
| tamanho igual ao da saída do canal | o canal usa outro tamanho do que o esperado |
| volume perto do alvo (±1,5) | a normalização não atingiu o alvo |

E duas linhas **informativas**, que você precisa ler:

- as **trilhas do arquivo original** (quantas, mono ou estéreo);
- **esquerdo × direito**: diz se o resultado tem canais diferentes (trilhas
  separadas) ou o mesmo sinal nos dois (mono duplicado).

### Ouvindo o arquivo convertido

O script imprime `OUVIR E CONFERIR: <caminho>`. Abra no VLC ou com
`ffplay <caminho>` e responda:

1. Esquerdo e direito soam como no arquivo original? (use fones; feche um
   lado de cada vez no VLC, se puder)
2. Alguma trilha de áudio ficou de fora ou duplicada?
3. O **volume** é parecido com o dos seus programas? Mais alto? Mais baixo?
4. A imagem está sem faixas estranhas, cortes ou distorção?
5. Se o original era entrelaçado (1080i), a imagem está sem "serrilhado"?

## 4. Se algo estiver errado: ajustar e repetir

O mapeamento de áudio é configurável. Repita o teste com outro valor:

```bash
python3 scripts/dev/commercials_smoke.py --user admin --password '...' \
  --sample /caminho/do/comercial.mxf --storage ~/ffp-teste/storage \
  --mapping first_two_mono --keep
```

| Sintoma | Tente |
|---|---|
| só um lado tem som | `--mapping first_two_mono` (ou `mix_all`) |
| som duplicado ou "cheio demais" | `--mapping first_stream` |
| faltam vozes ou músicas | `--mapping mix_all` |
| volume diferente do esperado | `--loudness-target -23` (ou o valor da sua norma) |

## 5. O que me enviar de volta

Cole na conversa:

1. O bloco **RESULTADO** que o script imprime no fim (é JSON; tem as trilhas
   do original, o resultado da conversão e as medidas).
2. Em poucas linhas, o que você **ouviu** (itens 1 a 3 acima) e **viu**
   (itens 4 e 5).
3. Se algo falhou: as últimas linhas do terminal do servidor
   (`ffplayout`), onde aparece o motivo.

Com isso eu ajusto o mapeamento padrão e considero a M2 aceita.

## Problemas comuns

| Mensagem | Causa e solução |
|---|---|
| `ffmpeg is not installed` | o `ffmpeg` não está no PATH do servidor |
| `the conversion failed: ... Unknown encoder 'libx264'` | o seu `ffmpeg` não tem `libx264`; instale uma build completa |
| `the audio is silent` | o arquivo não tem áudio audível (ou o mapeamento escolheu uma trilha vazia) |
| `the file has only one audio track, two are needed` | você usou `first_two_mono` em arquivo com uma trilha |
| `File type ... is not allowed` no envio | o servidor não tem a correção do MXF (use a versão mais nova da branch) |
| `Nao foi possivel falar com ...` | o servidor não está rodando ou a porta é outra (`--url`) |
| login falha | usuário ou senha errados, ou 2FA ativo (no setup acima use `"two_factor": false`) |
| `login respondeu 429` / "aguardando 21 s" | o servidor aceita só **3 logins por minuto** por endereço. O script espera sozinho e tenta de novo; ao repetir testes em sequência, isso é normal |
| `path must not point to a system directory` | a pasta está em `/tmp`, `/root`, `/var` ou outra do sistema; use uma pasta em `/home/<usuario>` |
