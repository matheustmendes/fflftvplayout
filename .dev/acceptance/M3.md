# Aceite da M3: grade semanal e compilador de intervalos

Roteiro para rodar **na sua máquina**, com a **grade real** da emissora.
O objetivo é confirmar o que a nuvem não consegue: que o dia montado é o que
a emissora esperaria, com os intervalos nos lugares certos.

Tempo estimado: 20 a 30 minutos.

## O que a M3 faz

Para uma data, o compilador junta três coisas e monta o dia:

1. **Os programas do dia da semana** (a "grade semanal"), na ordem em que você
   os cadastrou.
2. **As janelas de intervalo** daquele dia da semana (horário e duração).
3. **As campanhas que estão valendo na data** e seus spots já convertidos.

Cada intervalo vai para a **fronteira entre dois programas mais próxima do
horário pedido**. Ele é preenchido com spots por rodízio, respeitando o limite
por dia, a preferência de primeiro e último lugar, e sem repetir o mesmo
anunciante em seguida quando houver outra opção. O resultado é gravado como a
playlist da data, no formato que o playout já lê.

O rodízio é **determinístico**: planejar a mesma data duas vezes dá o mesmo
resultado; datas diferentes variam.

## O que você precisa

- O servidor de teste da M2 (banco separado, ver `.dev/acceptance/M2.md`).
- Os arquivos dos programas **dentro da pasta de storage** do canal.
- Ao menos dois ou três **spots prontos** (a M2: envie MXF e espere `ready`).
- Python 3.8 ou mais novo.

## 1. Cadastrar a grade de um dia da semana

`weekday` vai de 1 (segunda) a 7 (domingo). Só o arquivo é obrigatório: o
sistema lê a duração dele. `in_sec` e `out_sec` (opcionais) cortam o início e
o fim; `title` é opcional.

Crie um arquivo `quinta.json`:

```json
{
  "items": [
    { "source": "programas/bom-dia.mp4", "title": "Bom dia" },
    { "source": "programas/filme.mp4" },
    { "source": "programas/jornal.mp4", "title": "Jornal" }
  ]
}
```

E envie (o token vem do login, como na M2):

```bash
T=<access>
curl -s -X PUT http://127.0.0.1:8787/api/commercials/1/week-template/4 \
  -H "Authorization: Bearer $T" -H 'Content-Type: application/json' \
  -d @quinta.json
```

A resposta lista os programas com a duração lida de cada arquivo. Se um
arquivo não existir ou não puder ser lido, a resposta diz qual.

> A tela para montar a grade chega na M6. Por enquanto é por arquivo JSON.

## 2. Cadastrar as janelas de intervalo

Horário no relógio e duração em segundos. `tolerance_sec` é quanto o intervalo
pode ficar longe do horário pedido antes de o sistema avisar (padrão 60).

```bash
curl -s -X POST http://127.0.0.1:8787/api/commercials/1/break-windows \
  -H "Authorization: Bearer $T" -H 'Content-Type: application/json' \
  -d '{ "weekday": 4, "nominal_time": "20:00:00", "duration_sec": 180 }'
```

Repita para cada intervalo do dia.

## 3. Ver a prévia (nada é gravado)

```bash
python3 scripts/dev/commercials_plan_preview.py \
  --user admin --password '...' --date 2026-12-10
```

(troque a data por uma **quinta-feira** que caia dentro do período das suas
campanhas de teste). A saída mostra:

- a linha do tempo, com a **hora** de cada programa, spot e enchimento;
- os **intervalos**: horário pedido, horário em que de fato começam, quantos
  spots entraram;
- os **avisos**, em ordem de importância.

## 4. O que conferir

| Pergunta | Onde olhar |
|---|---|
| Os programas estão na ordem e nos horários que a emissora espera? | linha do tempo |
| Cada intervalo caiu entre dois programas, perto do horário pedido? | `INTERVALOS` e a linha do tempo |
| A soma fecha com o dia? | "Total" × "Tamanho do dia" |
| Os spots são das campanhas certas e da data certa? | títulos (`anunciante - spot`) |
| O mesmo anunciante aparece colado em outro? | seguidos na linha do tempo |
| O limite por dia e a posição primeiro/último funcionam? | rode a prévia de **5 a 10 datas seguidas** |
| O rodízio varia de um dia para o outro? | idem |

Para ver várias datas, rode o comando acima trocando `--date`.

### Avisos que você pode ver (e o que significam)

| Código | Significado |
|---|---|
| `break_off_grid` | a fronteira mais próxima está além da tolerância do intervalo. Ajuste a grade (um programa mais curto ou mais longo) ou o horário |
| `break_empty` / `break_underfilled` | faltam spots (ou o que tem não preenche o intervalo); o resto vira enchimento |
| `day_filled` | os programas e intervalos somam menos que o dia; o fim é completado com enchimento |
| `day_slightly_long` | passa de 1 a 5 s do dia; o último clipe é cortado |
| `day_too_long` | **erro**: passa de 5 s do dia. A playlist não é gravada |
| `no_free_boundary` | há mais intervalos que lugares entre programas |
| `no_programs` | **erro**: o dia da semana não tem grade cadastrada |
| `spot_file_missing` | o arquivo convertido de um spot sumiu do storage; o spot não é usado |

O **enchimento** é, hoje, o arquivo de filler configurado no canal (se for um
arquivo) ou preto e silêncio. A decisão do que a emissora prefere (vinheta,
slate) fica para você me dizer.

## 5. Gravar a playlist de uma data de teste

Só depois que a prévia estiver como esperado:

```bash
python3 scripts/dev/commercials_plan_preview.py \
  --user admin --password '...' --date 2026-12-10 --apply
```

Uma playlist que já exista **não é substituída** sem `--overwrite`. Um plano
com erro nunca é gravado.

Depois abra a tela do ffplayout, no editor de playlist daquela data: os spots
devem aparecer entre os programas, marcados como publicidade.

## 6. (Opcional) Ver tocar de verdade

Para ver a virada em torno de um intervalo sem esperar o dia chegar, suba o
playout com um relógio falso, alguns segundos antes do horário do intervalo:

```bash
./target/release/ffplayout -l 127.0.0.1:8787 --db ~/ffp-teste/ffplayout.db \
  --fake-time 2026-12-10T19:59:30-03:00
```

(ajuste o fuso para o do canal). Acompanhe a pré-visualização: o spot deve
entrar na hora e o programa seguinte voltar sem corte estranho nem silêncio.
Escute o volume em relação ao programa.

## 7. O que me enviar de volta

1. A saída da prévia de **três datas** (copie e cole o texto do terminal).
2. O que ficou **diferente do que a emissora faria**, com o motivo.
3. Os avisos que pareceram **errados** (falso alarme) ou que **faltaram**.
4. Respostas a estas decisões, olhando o resultado:
   - 60 s de tolerância para o horário do intervalo é razoável?
   - O que deve preencher um intervalo quando faltam spots: preto e silêncio,
     um arquivo de vinheta, ou deixar o programa seguinte entrar mais cedo?
   - Um dia que passa de 5 s da duração deve ser **bloqueado** (como hoje) ou
     **cortado** automaticamente no final?

## Problemas comuns

| Mensagem | Causa e solução |
|---|---|
| `no_programs` | falta cadastrar a grade do dia da semana da data (a quinta é o 4) |
| `HTTP 400 ... could not be read as media` | o arquivo não é um vídeo legível pelo FFmpeg |
| `HTTP 400 ... does not exist in the channel storage` | o caminho é relativo à pasta de storage do canal |
| `HTTP 409 ... already exists; confirm to replace it` | já há playlist para a data; use `--overwrite` se for de propósito |
| a prévia não mostra nenhum spot | nenhuma campanha vale na data, ou os spots não estão `ready`, ou os arquivos convertidos sumiram |
| os horários parecem deslocados | o início do dia do canal (`day_start`) não é meia-noite; a linha do tempo conta a partir dele (padrão `05:59:25`) |
